- [ ] 2.1 Delete the `budgetExhausted` computation and the `independentSpendFresh` trigger count from `gates.ts` AND EVERY CONSUMER — the same standard task 1.1 applies to the clause-(c) fields, and it is the budget fields that have a second home: `src/core/artifact-graph/instruction-loader.ts` declares `independentSpendFresh?: number` (line ~152) and projects it (line ~431) alongside the `budgetExhausted` read task 2.2 names. Check for a silent behaviour change while deleting: the trigger counted only FRESH passes, the report counts all including stale, so anything that read the trigger must be re-pointed deliberately rather than defaulted to the other field.
- [ ] 2.2 Remove the `BUDGET-SPENT` position-token labels from `gates.ts` and the `budgetExhausted` chip from `src/commands/workflow/status.ts`, and drop the `budgetExhausted` read in `src/core/artifact-graph/instruction-loader.ts`. - [ ] 2.2b Replace the `spend N/budget` RATIO at BOTH `status.ts` render sites — the live gate row (~line 226) and the superseded gate row (~line 205) — so the row reads the recorded figure alone (`[spend N]`). - [ ] 2.3 Remove the budget clause from the gate's reason string — the reason names the rule that fired, and spend is not a rule. Confirm the reason for an unpassed gate over its declared budget names ONLY the uncovered slot or the unresolved pass.

With the declaration inert, a recorded cost that appears only when an inert field happens to be present is incoherent — `independentSpend` SHALL report whenever the mode is derivable, declaration or not. Say what the surviving field bundle is, rather than leaving it derived: `budgetReportable` today gates ONE object of three fields, and after 2.1 removes `independentSpendFresh` the survivor is `{ budget, independentSpend }`. The SPEND field reports on mode alone; `budget` is present only when actually declared — never emitted as an undefined-valued key, since the projection's field names are normative.
- [ ] 2.4 Update the `budget` comment block in `schemas/spec-driven/schema.yaml` (which today describes the exhaustion boolean and the position token) to state that `budget` is a DECLARED EXPECTATION and that nothing consults it. Leave both `budget: 3` declarations in place — no version bump, no migration.
