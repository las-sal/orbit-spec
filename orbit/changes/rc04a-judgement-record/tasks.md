## 2. The ordering refusal (the one computed rule)

The check iterates PER ENTRY: each entry carries its own `formed_against`, two entries may cite different passes, and a valid entry must not rescue an invalid one. - [x] 2.3 An EMPTY `formed_against` is refused, and so is a missing `ratified_by`. Both are refusals of the record's defining properties, not validation pedantry: the first would admit a judgement formed against nothing, the second would let the engine guess whether a human ratified a decision.
- [x] 2.5 RUNTIME structural validation of the record, modelled directly on `validatePrFields` (`src/core/emit-composition.ts:486`) — which exists for exactly this reason, and whose comment says why: an emit carrying a malformed object "would otherwise sail through a seam advertised as fail-loud". Every refusal in this section names the offending value — the token, the command, the field — on stderr, writes NO file, and exits non-zero with empty stdout, matching the write gate's existing contract exactly.
