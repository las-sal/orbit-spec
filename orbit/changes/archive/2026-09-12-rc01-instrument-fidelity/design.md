## Context

Three instruments in this repo encode a remembered truth beside a real source they are not derived from (see explore.md, Premise): the `gh` stub in `test/integration/pr-lifecycle/harness.ts` is five hand-written branches that grew one rule per CRITICAL; the fidelity sweep in `test/core/templates/orbit-content-fidelity.test.ts` is a set of hand-written regexes with the same history; the `payloadFields` tables in `src/core/emit-composition.ts` (one per emit command) are hand-listed beside four schema references that document the same field sets. The D6 trail shows what that costs: two grammar CRITICALs that survived five passes, and an archive that could not record its own override until the table was patched in-flow.

Constraints: the suite must run on machines without `gh`; the stub is a standalone Node script written to a temp `bin/` dir at test time, so anything it shares with vitest tests must be loadable by plain `require`; NO ENGINE BEHAVIOR changes — the `src/` diff is schema-reference corrections (template constants, a generated-`references/` diff, expected) plus one read-only accessor, because the parity test cannot be green on the current tree otherwise; every existing harness case keeps passing. The change's final inventory is its diff, never a count restated in prose.

## Goals / Non-Goals

**Goals:**
- One recorded `gh` contract both the stub and the sweep derive from, captured from the real binary, re-captured only deliberately.
- The stub rejects what the real CLI rejects, with the real messages, and keeps enforcing orbit's own qualification contract.
- The sweep proves the grammar of every invocation-shaped snippet in the three PR references against the same contract.
- Every AI-supplied field a schema reference documents is accepted by the matching payload table, by test.

**Non-Goals:**
- Executing snippets (rc05). Simulating `gh` state (PR lifecycle transitions). A `git` contract (the harness runs real `git`). Parity for the emit commands without a schema reference — every command except review, address-reviews, audit-drift, and archive (rc07). Any change to engine BEHAVIOR (the two schema-reference corrections are mirror edits, not behavior).

## Decisions

- **D1 — A checked-in contract captured from the real CLI is the single source** (explore D-rc01-1, D-rc01-7, D-rc01-10; refined at the proposal walk 2026-09-11). `test/integration/pr-lifecycle/gh-contract.json`: `{ gh_version, availability_probe: { argv: ["--version"], stdout: "<captured banner>" }, commands: { "repo view": { usage, positional: { shape: "[<repository>]", required: false }, flags: [ { long: "--json", short: null, takes_value: true }, … ] }, "pr list": …, "pr create": …, "pr view": …, "pr edit": …, "pr ready": …, "pr merge": … }, rules: { repo_view_rejects_repo_flag: "unknown flag: --repo", pr_selector_required_with_repo: "argument required when using the --repo flag", pr_verbs_require_repo: true, repo_view_requires_positional: true } }`. Each FLAG ENTRY records the long name, the short alias when the FLAGS / INHERITED FLAGS line has one, and whether it TAKES A VALUE — derived from the line grammar (`-q, --jq expression` → short `-q`, takes a value; `--draft` with no TYPE → boolean); both facts are required by snippets that exist today (`gh pr create … --draft --base <resolved-base>` needs `--draft` known boolean; `gh pr view … -q .body` needs `-q` known as `--jq`'s alias). The SEVEN commands are exactly what the three PR references invoke; the availability probe is a separate top-level entry, not a command (its `--help` prints only the version banner, so it has no usage or flags). A verb the contract does not know is a sweep failure, so the set grows only when a reference grows. The two orbit-side rules (`pr_verbs_require_repo`, `repo_view_requires_positional`) encode the shared resolution's qualification contract, which the real CLI does NOT enforce (it would guess a repository) and the current stub does. Alternative rejected: parsing `gh --help` live at test time (needs `gh` everywhere; drifts with versions).
- **D2 — The capture script is the only thing that touches a real `gh`** (explore D-rc01-4). `scripts/capture-gh-contract.mjs` runs `gh <cmd> --help` per command (parsing USAGE and FLAGS / INHERITED FLAGS) and the two error probes (`gh repo view --repo x/y --json name`; `gh pr view --repo x/y --json isDraft` — both fail before any network request), records `gh --version`, and writes the file. Exposed as `npm run capture:gh`. A `contract-freshness` test asserts the file parses and carries a version; it never compares against the host. Re-capture is reviewed as a diff, the same discipline as `orbit fingerprint --refresh`.
- **D3 — One validator module, CommonJS, shared by the stub process and the tests** (refines explore D-rc01-2/D-rc01-3; refined at the proposal walk 2026-09-11). `test/integration/pr-lifecycle/gh-contract-validate.cjs` exports `validate(argv, contract) → { ok, command } | { ok: false, message }`. ARGV CONVENTION: `argv` EXCLUDES the leading `gh` token — the stub passes `process.argv.slice(2)` as-is; the sweep drops the first token of each snippet. COMMAND LOOKUP: the availability probe is matched first (argv equal to `["--version"]`), then the longest leading key in `contract.commands` (`pr view` before `pr`). TOKENIZING: walk the tokens after the command; a token matching a flag's long or short name is a flag — if `takes_value`, it consumes the next token (or its `=value` suffix); a boolean flag consumes nothing; any other token is a positional; the reference placeholders `<owner>/<repo>`, `<url>`, `<number>`, `<branch>`, `<path>`, `<resolved-base>` and their kin are positionals or values like any real token. CHECKS, in order: unknown flag → `unknown flag: <name>`; positional count against the shape; `repo_view_rejects_repo_flag`; `pr_selector_required_with_repo` (a selector-taking `pr` verb with `--repo` and zero positionals); `pr_verbs_require_repo`; `repo_view_requires_positional` (the orbit-side qualification the real CLI would not enforce). The stub `require()`s the module (it is a standalone script, so the module must be plain JS); the sweep imports the same file. Alternative rejected: duplicating the logic in TS for the sweep — the point is one source.
- **D4 — The stub keeps its scripted responses and loses its branches** (explore D-rc01-2). `installGhStub` writes a stub that logs argv, validates via D3 against the contract copied into `bin/`, and on success returns the scripted `defaultBranch` / `prList` exactly as today. Real messages on stderr, exit 1, no network.
- **D5 — The sweep extracts by SHAPE and lets the CONTRACT decide** (explore D-rc01-3; twice refined at review, 2026-09-12). Snippets are matched family-free (`` `gh <token> …` ``) so an invented or mistyped verb cannot escape; each is tokenized QUOTE-AWARE (a quoted value stays one token, matching the argv a shell hands the stub) with the leading `gh` dropped, and handed to the D3 validator, which treats placeholders as ordinary tokens. Copyable-vs-prose is decided by the contract, never a heuristic: a snippet is PROSE only when its command RESOLVES and nothing follows it (`gh repo view` naming the command), so a flagless but argumented invocation is still validated and an unresolved command is always validated. The test name states "grammar, not execution". Negative fixtures per rule — unqualified `repo view`, a `pr` verb without `--repo`, a selector-taking verb without its selector, an unknown verb with and without flags, and both value-parse cases — prove the sweep rejects what the stub rejects. (The two superseded rules are recorded because each was a remembered proxy the contract should have answered: a `repo|pr` family regex, then a carries-a-flag test.)
- **D6 — Schema-table parity derives the AI-supplied set by subtraction, over EVERY full-record block** (explore D-rc01-5, D-rc01-9; refined at the proposal walk 2026-09-11). For each of the four schema references (template constants in `review.ts`, `address-reviews.ts`, `audit-drift.ts`, `archive-change.ts`), parse EVERY JSON block whose top-level keys include `command` (a "full-record block" — the review reference has two: change modes and architecture mode), union their top-level keys, subtract one explicit engine-owned list (`command`, `timestamp`, `change`, `doc`, `kind`, `model`, `next_recommended`, `iteration`, plus the per-command computed keys the reference marks engine-owned), and assert the remainder ⊆ `payloadFields` for that command. The subtraction list is explicit and asserted non-empty, so a new engine-owned key is a visible edit. **The current tree fails this test twice, and the change fixes both as bounded mirror corrections (settled under R-crc-3, proposal walk):** (a) the audit-drift reference documents `context`, `caller`, `depth`, `flags`, `categories_skipped`, `findings_summary`, none of which its table accepts — the body's own field list matches the table, so the REFERENCE is the stale voice and is corrected to the table's set; (b) the review reference's architecture-mode block documents `findings_summary`, which the review table rejects and the engine's architecture-mode path never reads (it runs the `scorecard` rollup check) — the block and the body sentence claiming architecture mode "keeps" `findings_summary` are corrected to `scorecard`. Regression cases, in order: the archive table's four conditional fields (fixed 2026-09-11 in-flow), the audit-drift reference (a), the review architecture block (b). Rejected alternative: a known-divergence allowlist in the test with the fixes deferred to rc07 — it keeps `src/` untouched at the price of recording a remembered exception, the exact anti-pattern rc01 retires. Also rejected: generating the tables from the references (inverts the documented authority; revisit under rc07).
- **D7 — Spec footprint is two ADDED requirements** (explore D-rc01-6): `orbit-pr-lifecycle` (the instrument contract) and `orbit-emit-composition` (the parity). No MODIFIED blocks, so nothing to fingerprint.

## Risks / Trade-offs

- [The contract goes stale against a newer `gh`] → the file records the version; re-capture is a scripted diff; a real-CLI behavior change shows up as a contract diff, never as a silent stub acceptance.
- [The `--help` parser mis-parses a command's FLAGS section] → the capture script writes a per-command `usage` line verbatim beside the parsed fields, and the freshness test asserts each command has ≥ 1 flag and a usage line; the two error rules are recorded from observed stderr, not parsed.
- [The CommonJS validator diverges from the TS style of the repo] → it is one small file with a test of its own; the stub's need for `require` is the constraint, stated in the file header.
- [A placeholder in a snippet hides a real grammar defect] → placeholders are a closed list; anything else must be a real token the contract accepts.
- [The engine-owned subtraction list drifts] → it is asserted non-empty and reviewed like any list; a key missing from it fails the parity test loudly rather than passing silently.
- [The two mirror corrections are `src/` edits in a "tests only" stage] → they change no behavior (template constants that render into `references/*.md`), the generated-surface diff is exactly two reference files, and each is a named regression case; the stage's non-goal is engine BEHAVIOR change, stated as such.

## Migration Plan

None: tests, one script, and two schema-reference corrections. Every existing harness case must pass unchanged; the two grammar cases added in D6 (the flag form rejected; the positional form accepted) become the first contract-derived cases. After the reference corrections, `node bin/orbit.js update --force` regenerates exactly two `references/` files (audit-drift's and review's schema references) and nothing else.

## Alternatives considered

From explore.md, Considered & out: parsing `--help` live at test time (rejected: nondeterministic across machines); a fuller `gh` simulator (rejected: rc12 territory); generating payload tables from the schema references (rejected for now: inverts authority, touches the engine; revisit under rc07).
