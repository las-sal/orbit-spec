This brief says what this change did, from what its history holds. Text under a heading is quoted from the change's records as they were written; orbit writes the rest.

- Program: architecture doc `automate-dev-flow`, stage `tripwires`

## What was built

orbit now has tripwires, built as sensors behind one contract, and its first sensor: it notices when a change edits code its plan did not name, past a limit (more than 40 changed lines in one such file, or more than a fifth of the change's changed lines of code in such files). The plan it compares against is the one that stood when building began, so the work cannot move it. Every review, building step, walk and archive records each sensor's reading, quiet ones included, and the change's brief lists every finding once, with its evidence and any stop that asked about it. With nothing configured, nothing else the user sees or is asked changes.

## New seams

One new setting, `tripwires`, in the project's config. Set a sensor to halt and a finding writes a stop for the user to answer, which a granted chain stops at; a supervised session still ends as before, and the stop waits in the brief. Once the user answers a stop, the same finding is not asked about again.
