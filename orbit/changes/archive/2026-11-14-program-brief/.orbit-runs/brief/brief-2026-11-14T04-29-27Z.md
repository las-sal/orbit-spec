## What was built

A project can now make each change wait for the user's sign-off before it lands. With the sign-off setting set to change, the archive shows the user the change's saved brief in full and asks them to sign off or decline before anything is synced or moved. A decline stops the archive, records the user's reason, and leaves the change active. orbit records each answer against the exact text the user read, and a damaged or hand-made answer never lifts the wait, so a signature over different text does not lift the wait, and a brief saved again with the same text is not asked about again. With the setting on, the system review's reading step also reads the change's account, so the brief the user signs has been checked by a clean reader. With the setting absent or off, nothing the user sees or is asked changes.

## New seams

One new question: with the sign-off setting set to change, the archive asks the user to sign off on or decline the change's brief, after showing it in full, before anything is synced or moved; on a decline with no reason given, it asks for the reason. A chained archive asks it too, and the chain stops after it. The sign-off setting is new: only its change value alters what happens, adding that question and the account's reading at the system review. A value orbit does not read is reported in one line at each archive, and nothing waits.
