## MODIFIED Requirements

### Requirement: `explore.md` five-section format

The system SHALL use a fixed format for `explore.md`: Premise, **Mechanism**, Decisions, Open questions, Considered & out, References. Open-question entries SHALL carry a `Standing recommendation:` slot — `Standing recommendation: <the current leaning>` or `Standing recommendation: none yet` — so a pending leaning discussed in conversation has a named, file-resident home (D-arc Stage D5, leak-hardening layer 1: AIs fill template slots far more reliably than they obey prose rules; the slot's RECORDED LEANING is what the emit surface's attestation counts — a `none yet` value attests an honestly empty slot, not a leaning, per `orbit-emit-composition`'s membership criterion).

**A Decision is a RULE when it has a DOMAIN OF SITUATIONS.** A Decision ENTRY may carry more than one CLAIM, and the test applies PER CLAIM, not per entry: an entry may state a finding and still embed a rule in a consequence clause. Each claim is a FACT about what happened (about one world; falsifiable by evidence, no domain), a SCOPE choice (in / out / deferred; one-off, no domain), or a RULE constraining how something must be done (has a domain). An entry whose rule-clause is INCIDENTAL — a consequence stated in passing rather than the entry's subject — owes the same closed enumeration, or an explicit note that the clause is illustrative and governs no situations. The test is "in which SITUATIONS does this apply?" — a SET means rule, and that set is the domain. The test is deliberately GRAMMAR-INDEPENDENT: a form-based test such as "states a conditional" lets an author write a rule in prose carrying no WHEN/THEN and fall outside it, while a rule that governs no situations constrains nothing.

**A DECISION ENTRY CARRIES A STABLE IDENTIFIER.** Each entry in Decisions begins with an identifier slot — `**<ID>**` where `<ID>` is unique within the file — so a rule can be referenced by something a reader and a parser both see. Without it the Decisions section is dated prose, and nothing downstream can name which rule is which.

**A RULE'S MECHANISM ENTRY HAS A NAMED SHAPE**, so the section is parseable rather than merely conventional. Each entry opens with the rule's identifier, then carries three named slots: `Domain:` (the closed enumeration), `Closure:` (one of `DERIVED` / `SOURCED` / `BOUNDED`, and for BOUNDED the residual), and one line per move recording its disposition. The slot idiom follows the precedent this capability already states — AIs fill template slots far more reliably than they obey prose rules — which is why `Standing recommendation:` is a slot and not an instruction.

**AN ENTRY LEAVES THE CLOSURE OBLIGATION BY A NAMED DISPOSITION, not by a word an author chooses.** A Decisions entry carries `Disposition:` with one of: `live` (the default when the slot is absent), `superseded` (with a pointer to what replaced it), `assigned` (with the stage that owns it now), or `illustrative` (the rule-clause is incidental and governs no situations). A rule is IN the closure obligation only while its disposition is `live`. Fixing the vocabulary is the point: this convention's own first artifact used SUPERSEDED, OVERTAKEN and a bare pointer interchangeably, and an annotation an engine must recognise cannot be whatever word fit the sentence.

**Every RULE carries a CLOSED ENUMERATION of its domain in the Mechanism section.** Closure has three DECLARED forms. **This taxonomy is itself BOUNDED, not derived**: the three below are the justifications observed on this program's record, and the residual is stated — a justification that fits none of them is a finding about the taxonomy, recorded as such. Declaring the taxonomy DERIVED would rest on a structure the author invented, which is the loophole DERIVED leaves open.

| form | the enumeration is closed because |
|---|---|
| **DERIVED** | the domain is generated by a structure whose parts are known, and every part is covered |
| **SOURCED** | the domain is a finite set an authority defines — a type, a code branch set, a grep over a named file — and every member is covered |
| **BOUNDED** | the domain is open; the members are named AND an explicit residual is stated |

The enumeration SHALL DECLARE which form it is, so a reader checks the justification rather than the list's plausibility. **"I can name no more" is NOT a form**: it is the state every failed enumeration on this program's record was in, and from the inside it is indistinguishable from closure. Classifying a record FALSIFIES an enumeration but never closes one — a classification can find a missing member and can never prove none remains.

#### Scenario: Section order

- **WHEN** an `explore.md` file is created
- **THEN** the sections appear in this order: Premise, Mechanism, Decisions, Open questions, Considered & out, References

#### Scenario: Status header

- **WHEN** an `explore.md` file is created
- **THEN** it includes a `> **Status**: exploring...` header indicating the file is a pre-propose record

#### Scenario: Open questions carry the standing-recommendation slot

- **WHEN** an open question is captured in `explore.md`
- **THEN** its entry includes a `Standing recommendation:` line — the current leaning, or the literal `none yet`; an entry lacking the slot is a format violation the explore body corrects on next touch

#### Scenario: A Decision with a domain is a rule

- **WHEN** a Decision is captured and asking "in which situations does this apply?" yields a SET of situations rather than one situation or none
- **THEN** it is a RULE and requires a closed enumeration of that set in the Mechanism section, regardless of whether its prose is phrased as a conditional

#### Scenario: A Decision without a domain is not a rule

- **WHEN** a Decision states a fact about what happened, or a one-off scope choice
- **THEN** it has no domain, requires no enumeration, and its absence from the Mechanism section is not a format violation

#### Scenario: An enumeration declares its closure form

- **WHEN** a closed enumeration is written in the Mechanism section
- **THEN** it names which of DERIVED, SOURCED or BOUNDED justifies its closure; an enumeration that names no form is unclosed regardless of how complete it appears
