## What was built

The user can now choose to sign off once per program rather than once per change. With the sign-off setting set to program, no change's archive waits; instead, once every stage of a program is finished and its closing review is recorded, the architect session shows the user the program's saved brief whole and asks them to sign off or decline. The program is done only once they sign, and when the changes of a program share one pull request, its ready step is offered only then. A decline is recorded with the user's reason, and the next architect session asks again. A copy of the program's brief is now saved whenever the program is finished and its brief has changed, under every setting, and it can be saved and its hold read by hand. Under the program setting, each change's account is checked by a reader at review, as under the change setting.

## New terms

- **closing review**: the architecture review of the program recorded after the last of its changes was archived (defined in account-2026-11-16T15-37-43Z.json)
- **ended**: a stage the user declared over without meeting its exit criteria, marked in the doc (defined in ledger-2026-11-16T18-16-01Z.json)
- **finished**: every stage the program declares is complete, awaiting ratification or ended, and no open change or exploration belongs to the program (defined in account-2026-11-16T15-37-43Z.json)
- **hold**: a wait for the user's sign-off before the work counts as done (defined in account-2026-11-16T15-37-43Z.json)

## New seams

Under the program sign-off setting, the architect session asks a new question: sign off on the program's brief, or decline, giving a reason. It is asked again in a later session when a newer copy of the brief differs from the signed one and the program's pull request can still be marked ready, or when a change of the program was archived after the signature. The setting now accepts program beside change; at the default nothing new is asked.
